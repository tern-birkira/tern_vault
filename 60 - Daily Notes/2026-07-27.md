## Merge Request


## What[](https://app.clickup.com/t/9012329445/what "Issue in ClickUp")

Adds extended-field editing (a second field layout merged onto Correlated/FlightPlanTrack labels), a new "Active" visibility state, an "In Holding" toggle, and working control-state/variant pickers in the track label editor.

## How[](https://app.clickup.com/t/9012329445/how "Issue in ClickUp")

Every add/select action now carries an `extended` flag that routes it to one of two targets, the base layout or `m_extendedLayout` through one shared handler on the controller (`addFieldToLayout` / `selectFieldInLayout`), so nothing's duplicated per layout. The same flag drives the QML side too: `AddField.qml` and the new shared `FieldRowRepeater.qml` use it to call `addExtendedField`/`selectExtendedField` instead of the base-layout versions. One new signal/slot connection wires `FieldsProxyModel::addExtendedFieldRequested` to the controller's `addFieldToExtendedLayout`, alongside the existing `addFieldRequested` route. The header tabs (display state, control state, variant) now route straight to controller properties (`activeVisibility`, `activeControlType`, `activeType`) instead of local UI-only strings, so the existing runtime-changed, reevaluate-visibility connection picks them up automatically.
