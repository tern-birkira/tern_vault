
## The chain of events today

1. User clicks a field → `FieldRowRepeater`'s `MouseArea.onClicked` fires:
    
    ```js
    fieldRowRepeaterId.fieldPropertiesPopup.openFieldProperties( model, fieldMouseAreaId, mouse.x, mouse.y )
    ```
    
    The `model` here is **not** the `FieldListModel*` itself — it's the QML delegate-context object that `Repeater` (whose `model:` is a `FieldListModel`) creates _for that specific index_. It's a live, role-backed accessor: reading `model.visibleInHolding` reads role data at that index, writing `model.visibleInHolding = true` calls `setData()` at that index.
    
2. `openFieldProperties` stores that context object in `fieldPropertiesRootId.model`. `AppearanceBehaviorRow` then binds its checkboxes to `fieldPropertiesRootId.model.visibleInHolding`, etc.
    
3. Because it's a role-backed accessor, it _does_ update live when `dataChanged` fires for that index — that part works as designed. The problem is **what "that index" means.**
    

## Why moving between fieldList instances breaks it

`void TrackLabelModel::moveField( int fromRow, int fromCol, int toRow, int toCol )`  inserts `FieldInterface*` pointer stored at `(fromRow, fromCol)` into `(toRow, toCol)`. The QML delegate-context object is now non existant in source `fieldListModel`, hence it tracks nothing, and the popup menu reflects that, doesn't show relevant data (not even for any other delegate-context object from fieldList)

But the popup's `model` was captured as "whatever occupies index `fromCol`" at click time, not "the specific field the user clicked on." So:

This is an **index-identity vs. object-identity** bug: the popup tracks a position, not a field.


## Fix
**Option B — keep index-tracking, but keep the index in sync.** This is presumably what `rowIndex` / `fieldIndex` on `fieldPropertiesRootId` were meant for, but they're currently set nowhere and never used. You'd need to:

- Set them in `openFieldProperties`.
- Connect to `FieldListModel::moveFieldRequested`   and, if the move affects `fieldIndex` in the currently-open row, update `fieldIndex` to follow the field rather than leaving it pinned to the old position.
- Re-derive `model` from the updated `rowIndex`/`fieldIndex` rather than caching the original context object. (this can be done with some kind of refreshing)
